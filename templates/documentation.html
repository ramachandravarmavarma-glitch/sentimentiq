1. What is Sentiment Analysis?

Sentiment Analysis (also known as opinion mining) is a computational linguistics and Natural Language Processing (NLP) methodology used to systematically identify, extract, and quantify emotional tone, subjective attitudes, and affective states present in written text.

In enterprise and software ecosystems, sentiment analysis is applied to customer reviews, brand mentions, social discussions, feedback surveys, and support tickets to monitor public perception, detect early grievances, and measure user satisfaction.

2. What is TextBlob?

TextBlob is a Python library designed for processing textual data. Built on top of the Natural Language Toolkit (NLTK) and Pattern libraries, TextBlob exposes clean, Pythonic APIs for common NLP tasks, including part-of-speech tagging, noun phrase extraction, sentiment analysis, and tokenization.

# Core TextBlob Sentiment Evaluation
from textblob import TextBlob

blob = TextBlob("SentimentIQ is delightfully accurate and reliable!")
polarity = blob.sentiment.polarity # returns float [-1.0, 1.0]
subjectivity = blob.sentiment.subjectivity # returns float [0.0, 1.0]

3. Polarity and Subjectivity Mathematical Ranges

Polarity Spectrum [-1.0 to +1.0]

Polarity quantifies the emotional valence of text:

  • -1.00: Intensely Negative (grief, outrage, disgust)
  • 0.00: Perfectly Neutral or emotionally balanced
  • +1.00: Intensely Positive (admiration, joy, delight)

Subjectivity Spectrum [0.0 to 1.0]

Subjectivity quantifies factual statements versus personal bias:

  • 0.00: Purely Objective (empirical facts, data, logs)
  • 0.50: Balanced mix of objective context and interpretation
  • 1.00: Purely Subjective (personal beliefs, feelings, bias)

4. Documented Classification Thresholds

SentimentIQ adheres strictly to documented, empirical sentiment thresholds and does not invent speculative emotional sub-states:

Classification Polarity Rule Description
POSITIVE Polarity > +0.10 Expresses approval, delight, satisfaction, optimism, or recommendation.
NEGATIVE Polarity < -0.10 Expresses dissatisfaction, malfunction, criticism, anger, or frustration.
NEUTRAL -0.10 ≤ Polarity ≤ +0.10 Factual, informative, descriptive, or devoid of significant emotional polarity.

SentimentIQ is structured following enterprise Flask Application Factory design patterns, modular Blueprints, and clean separation of concerns:

sentimentiq/
├── app.py                   # Application factory `create_app()`
├── config.py               # Environment settings & threshold configs
├── database/

│   └── models.py           # User and SentimentResult DB schemas
├── routes/
│   ├── auth.py             # Registration, Login, Logout, `@login_required`
│   ├── main.py             # Landing page, settings, diagnostics
│   ├── sentiment.py        # Dashboard and `/api/analyze` endpoints
│   ├── history.py          # History filtering, inspection, and Pandas CSV export
│   └── analytics.py        # Database analytics & Chart.js API
├── services/
│   └── sentiment_service.py # Pure TextBlob NLP evaluation logic
├── templates/              # Semantic Jinja2 HTML5 views
├── static/                 # Custom CSS, Chart.js engine, dynamic JS
└── tests/                  # Automated unit & route integration tests

6. Database Schema & Data Isolation

SentimentIQ utilizes SQLite via SQLAlchemy ORM. All data is isolated by user_id foreign key relationships so each user only sees and exports their private data:

Table: users
  • id (INTEGER PRIMARY KEY)
  • username (VARCHAR(80) UNIQUE)
  • email (VARCHAR(120) UNIQUE)
  • password_hash (VARCHAR(256))
  • created_at (DATETIME)
Table: sentiment_results
  • id (INTEGER PRIMARY KEY)
  • user_id (INTEGER FK -> users.id)
  • text (TEXT NOT NULL)
  • sentiment (VARCHAR(20))
  • polarity (FLOAT NOT NULL)
  • subjectivity (FLOAT NOT NULL)
  • created_at (DATETIME)
